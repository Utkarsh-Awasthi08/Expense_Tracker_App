# gatewayService

Spring Cloud Gateway (WebFlux, Boot 3.5.16 / Cloud 2025.0.3, Java 21) on `:8000`; it replaces Kong and is the only public entry point besides authService on `127.0.0.1:9898`.
Routes: `/auth/v1/**` to auth (`AUTH_SERVICE_URL`), `/user/v1/**` to user (`USER_SERVICE_URL`), `/expense/v1/**` to expense (`EXPENSE_SERVICE_URL`), `/sms/v1/<x>` to dsService `/v1/ds/<x>` (`DS_SERVICE_URL`, 120 s timeout, 5 s connect).
Public: only `POST /auth/v1/{signup,login,otp/request,otp/verify,refreshToken,logout}` and `GET /actuator/health[/**]` (exact raw-path match); everything else needs `Authorization: Bearer <jwt>`, else 401 JSON (`WWW-Authenticate: Bearer`). Only `health` is exposed by actuator.
**Why signup/login are still public here:** this gateway is mid-migration to phone-number + OTP login. authService has not shipped the OTP controllers yet (no route for `otp/request`/`otp/verify`) or the coordinated DB migration, so `signup`/`login` (the contract still pinned in `docs/CONTRACTS.md`) remain the only auth entry points that actually work; `otp/request`/`otp/verify` are wired here already so no further gateway change is needed once authService ships its half. Cutting signup/login out of the public set before that happens would require a bearer token to reach login itself, which no unauthenticated client could ever obtain — a total lockout. Once authService ships the OTP controllers and updates `docs/CONTRACTS.md` in the same change, drop `signup`/`login` from `PublicRoutes.AUTH_POST_PATHS` and the `auth-public` route predicate in a coordinated follow-up.
On those public routes no bearer token is authenticated at all, so a stale or garbage `Authorization` header (a mobile client attaches its expired access token to signup, login, OTP request/verify, refresh and logout) cannot cause a 401, and the header is removed before the request is forwarded (authService's own resource server would reject the stale token too). Near misses of a public path (trailing slash, `//`, `;`, percent-encoding, another case, another method) keep strict authentication.
JWT: RS256 only (RS384, RS512, PS256, HS256 and `alg=none` are rejected, also when signed with the right key), keys fetched lazily from `JWT_JWKS_URI` (default `http://localhost:9898/auth/v1/.well-known/jwks.json`), `iss` must equal `JWT_ISSUER` (default `expense-tracker-auth`), `sub` must be a UUID. The gateway boots while authService is down; tokens then get 503 JSON until the JWKS is reachable.
Env: `AUTH_SERVICE_URL`, `USER_SERVICE_URL`, `EXPENSE_SERVICE_URL`, `DS_SERVICE_URL`, `JWT_JWKS_URI`, `JWT_ISSUER` (all have dev defaults; nothing secret is needed, the gateway only holds public keys).
Trust model: for every request the gateway first strips the identity headers `X-User-Id` and `X-User-Roles` and their look-alikes `Remote-User`, `X-User`, `X-UserId`, `X-Auth-User`, `X-Remote-User`, `X-Forwarded-User`, `X-Authenticated-User`, plus the `X-HTTP-Method-Override` family (`X-HTTP-Method`, `X-Method-Override`). Matching is case-insensitive, all values and repeated lines are removed, and `_` is read as `-` (so `x_user_id`, `X-User_Id`, `X_User_Roles`, `REMOTE_USER` are gone too, for backends that map underscores to hyphens); this happens on public routes and for unauthenticated calls as well. Then it sets `X-User-Id` = token `sub` and `X-User-Roles` = comma-joined `roles` claim. A protected request is forwarded with exactly one `Authorization` header, the first one, which is the one the gateway authenticated (repeated lines are collapsed); public routes forward none.
Downstream services trust `X-User-Id` only because their ports are not published (only the gateway can reach them); the real hardening, each service validating the JWT itself, is deferred. Never publish backend ports.
Ambiguous paths (`//`, `;`, `..`, encoded `%2e` `%2f` `%5c` `%00`, backslash, and percent-encoded bytes that cannot occur in UTF-8: overlong lead bytes `%c0` `%c1` and `%f5` to `%ff`, any case) are rejected with 400 before routing; near misses of a public path (trailing slash, `%6cogin`, upper case) get 401.
Errors use the pinned body `{timestamp,status,error,code,message,path}`; upstream failures are 502/504 with code `INTERNAL` and a fixed message (details go to the log only).
Known gaps: no rate limiting (an unknown `kid` triggers one JWKS refetch per request), no CORS config.
Run: `export JAVA_HOME=$(/usr/libexec/java_home -v 21) && ./gradlew clean test bootJar`; tests use in-memory RSA keys and stub servers (no Docker, no network).
